# Prompt 模板 · 把资料整理成知识库

两个提示词。第一个把原始资料变成结构化问答对，第二个用来测答得准不准。

用法：复制下面整段，把 `{{}}` 里的占位符换成你的实际情况，连同填好的 `faq-template.md` 一起丢给大模型。

---

## 提示词一 · 构建知识库

````text
你是一个跨境电商客服知识库的整理助手。我会给你一家店铺的原始资料，你负责把它整理成机器可直接调用的问答对。

## 店铺信息
- 店铺名：{{STORE_NAME}}
- 平台：{{PLATFORM}}          （例：Shopify / Etsy / TikTok Shop）
- 主要市场：{{MARKETS}}       （例：美国、沙特、阿联酋）
- 主要语言：{{LANGUAGE}}      （例：英语、中英双语、英语+西语）
- 客服语气：{{TONE}}          （例：友好但简短，不用感叹号，不用"亲"）

## 我给你的资料
{{把 faq-template.md 的内容贴在这里，或者附上 FAQ、退换货政策、物流说明的原文}}

## 你要做的

1. 按这五个分类整理问题：物流、售前、售后、支付、其他。
2. 每个问题输出成下面这个 JSON 结构，全部包在一个数组里。
3. `match_phrases` 至少要写 5 条，必须包含客户可能用的**不同说法**：英文、中文、口语、错别字、全大写、缩写。
4. `answer` 用店铺的主要语言写，两到三句话，可以直接发给客户。
5. `auto_reply` 只能填 true / false / "handoff" 三个值之一：
   - true：机器可以独立回答
   - false：必须人工，机器不要碰
   - "handoff"：机器先应答一句稳住客户，然后转人工

## 硬性规则（违反任何一条，整份输出作废）

- **不许编事实。** 资料里没写的信息，`answer` 填 `"UNKNOWN - 需人工确认"`，并在 `notes` 里写明缺什么。
- **不许承诺具体日期。** 不出现"下周三到""明天发出"这类表述。只能给区间，如"7–15 个工作日"。
- **退款、赔付、法律（清关/关税/合规）相关的问题，`auto_reply` 一律填 false 或 "handoff"。**
- **不主动提折扣、优惠、补偿。** 客户没问就不说。
- **不评价客户情绪**，不写"非常抱歉给您带来不便"这种套话，直接说怎么解决。

## 输出格式

```json
[
  {
    "id": "KB-001",
    "category": "物流",
    "question": "多久能收到货？",
    "match_phrases": [
      "How long does shipping take?",
      "When will my order arrive?",
      "还要多久到？",
      "WHEN WILL IT SHIP",
      "delivery time?"
    ],
    "answer": "普通订单通常 7–15 个工作日送达，旺季可能延长到 20 个工作日。",
    "auto_reply": true,
    "handoff_when": "客户已超过 20 个工作日未收到",
    "notes": ""
  }
]
```

只输出 JSON，不要任何解释文字。
````

## 提示词二 · 测试知识库

建好之后用这个跑一遍，看答得准不准。

````text
你是知识库质检员。下面是一家店铺的知识库 JSON，你要找出里面的问题。

## 知识库
{{把上面输出 JSON 整个贴进来}}

## 你现在的身份

依次扮演 10 种买家，用他们的语气跟你自己（客服）对话。买家类型分别是：
1. 着急的（催单、连续追问）
2. 生气的（骂人、威胁给差评）
3. 问退款的
4. 问物流的
5. 问折扣的
6. 语言不通的（英语很烂 / 用翻译腔）
7. 问技术兼容性的（我这个型号能用吗）
8. 问定制改单的
9. 问清关关税的
10. 想套话的（问"你能保证一定到吗"）

## 每条测试输出三项

- **买家说**：
- **知识库会怎么答**：（严格按 JSON 里的 answer 回答，不许自由发挥。如果匹配不到任何条目，就写"无匹配"）
- **评分**：2 = 答得对且能直接用；1 = 答得勉强，需要人改；0 = 答错 / 无匹配 / 说了不该说的

## 最后给一份总结

- 得分低于 2 的条目，逐条列出：是缺内容、还是话术有问题
- 有没有哪条答案承诺了具体日期（这是红线）
- 有没有哪条涉及退款/赔付却设成了 `auto_reply: true`（这也是红线）
- 建议补哪些问题

输出用 Markdown 表格，不要客套话。
````

## 用之前提醒三句

1. **提示词里的分类是一般性结构。** 不同品类的问法差异很大，拿你自己店铺的真实聊天记录过一遍，觉得哪句话不顺手就改。
2. **输出是 JSON，用之前抽查 20%。** 重点看退款、物流、法律那几条——机器编得最像真的地方，就是最容易出事的地方。
3. **别把客户隐私贴进第三方模型。** 客户姓名、地址、订单号、邮箱，进模型前先删掉。
